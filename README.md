# Youthcare Infoflow Survey: analysis pipeline

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.23598059.svg)](https://doi.org/10.5281/zenodo.23598059)

Analysis code for an exploratory, cross-sectional Microsoft Forms survey on information
fragmentation in Dutch child and adolescent mental-health care, at two organisations
(N=You and Levvel). It cleans and harmonises the per-persona exports, computes the
descriptive tables and figures used in the paper, and prepares the open-text for
qualitative coding.

The study is descriptive and exploratory: no inferential testing, ranking, or
representativeness/causal claims.

- Personas: parents, child respondents (aged 12-18), care providers, intake coordinators.
- Reporting groups: Families = parents + child respondents; Professionals = care providers
  + intake coordinators.
- Themes: Experience, Overview/Insight, Information exchange, Control, Effort.
- Analysed sample: N=72 (Families 41, Professionals 31); that is 73 submissions minus one
  screener-ineligible child respondent.

## What this repository does and does not contain

Included (public): the analysis code, the mapping workbooks, aggregate results, figures,
and item/bridge/codebook metadata. Excluded (private, git-ignored): the raw Microsoft
Forms exports (they contain respondent e-mail), the respondent-level `analysis_long`, the
open-text corpus, the coded qualitative workbook, and individual feedback. Raw and
open-text data stay private because free text and small subgroups can be indirectly
identifying.

## Layout

```
run_all.py                       one-command canonical pipeline (+ tidy + release gate)
export_publication_artifacts.py  builds the metadata, bridges, results tables and codebook
export_s1_questionnaires.py      builds Additional file 1 (the four questionnaires)
make_figures.py                  builds Figures 1-5 from the final results tables
make_s4_dotplots.py              builds Additional file 4 (Top-2 dot-plots, one PDF)
build_s6_supplement.py           builds the qualitative quote table from the (private)
                                 redacted review; NOT published (participant quotes)
validate_release.py              seven release assertions -> VALIDATION_REPORT.md
check_release.py                 pre-publish safety gate (no private paths / e-mails)
run_*.py                         individual pipeline stages
src/                             shared library (io, mapping, transform, qc, labels, reporting)
data/
  raw/            PRIVATE  8 Forms exports (N=You/, Levvel/)
  mapping/                intermediate_bundle_mapping_table_v6.xlsx, bridge_map_with_workload_links_v08.xlsx
  qualitative/    PRIVATE  coded open-text workbook + redacted quote review (manual input)
metadata/         item_dictionary.csv, questionnaire_items_source.csv (questionnaire source),
                  bridge_matrix.csv (bridges), label_overrides_en.csv
outputs/          built by run_all.py; not committed except figures/Figure_1..5
  aggregate_item_results.csv     results A     persona_specific_results.csv   results B
  analysis_long.csv/.xlsx        PRIVATE (row-level intermediate)
  figures/        Figure_1..5 (article body, committed), S4_pooled_dotplots/ (dot-plots)
  journal_upload/ the five upload files, named as BMC asks (local only)
  summaries/      verified intermediate summaries (provenance)
  themes/open_questions/         PRIVATE (open-text exports)
  _legacy/        retained non-canonical/superseded outputs
supplement/       Additional files 1-5 of the paper (rebuilt by run_all.py; see Outputs)
CITATION.cff / LICENSE           citation + licence
ANALYSIS_DECISIONS.md            analytical decisions + conventions (single source)
VALIDATION_REPORT.md             generated by validate_release.py (git-ignored)
requirements.txt / requirements-lock.txt · .gitignore
```

## Environment

Supported: Python 3.9 to 3.12 (developed on 3.9.6). Cross-platform.

```bash
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements-lock.txt  # exact pinned versions (reproducible)
```

## Inputs an authorised user needs

- `data/raw/N=You/*.xlsx` and `data/raw/Levvel/*.xlsx`: the 8 persona exports. File names
  must contain a persona keyword (ouders / jongeren / hulpverleners / aanmeldteam).
- `data/mapping/*.xlsx`: the two mapping workbooks (provided).
- `data/qualitative/open_questions_all_themes_coded.xlsx`: needed for the codebook (Additional file 5)
  (optional; the quantitative pipeline runs without it).

## Running

```bash
python run_all.py            # full pipeline: builds Additional files 1-5 + Figures 1-5,
                             # tidies outputs/, then runs the release gate
```

`run_all.py` exits non-zero if any of the seven release assertions fail. Individual stages
(run `run_build_analysis_long.py` first): see the ordered list in `run_all.py`.

## Outputs

`supplement/` holds the paper's additional files, numbered as in the article. The five files
marked *upload* are the ones submitted to the journal; `run_all.py` also copies them, named
exactly "Additional file 1" to "Additional file 5", to `outputs/journal_upload/`.

| Additional file | Contents | File(s) in `supplement/` |
|---|---|---|
| 1 | The four persona questionnaires: Dutch as administered, with English translation | `Additional_file_1_questionnaire_items.csv` (*upload*); `Additional_file_1_questionnaires.md` is a readable version with an explanatory preamble |
| 2 | Confirmed Family/Professional bridges | `Additional_file_2_bridge_matrix.csv` (*upload*) |
| 3 | Results tables: A pooled groups, B per persona, C persona differences with the highlight flag, plus a column dictionary | `Additional_file_3_results.xlsx` (*upload*, one sheet per table); the same tables as CSV in `Additional_file_3A_…`, `3B_…`, `3C_…` and `Additional_file_3_column_dictionary.csv` |
| 4 | Top-2 dot-plots, one theme per page | `Additional_file_4_Top2_dotplots.pdf` (*upload*) |
| 5 | Codebook of the open-text analysis: themes, subthemes and how often each was coded | `Additional_file_5_codebook.csv` (*upload*) |

The qualitative quote table is not published: even redacted, free-text quotes from small
subgroups can be indirectly identifying. It is built to
`outputs/S6_qualitative_patterns_PRIVATE.csv` for the authors only.

Article-body figures (Figures 1-5) are in `outputs/figures/`. Generation sources: `metadata/`
(questionnaire source, bridges), `outputs/aggregate_item_results.csv` and
`outputs/persona_specific_results.csv` (results tables A and B). Apart from Figures 1-5,
everything under `outputs/` is rebuilt locally by `run_all.py` and is not in this repository;
the published copies of the results tables are in Additional file 3. A local run also writes
verified intermediate summaries to `outputs/summaries/` and keeps non-canonical outputs
under `outputs/_legacy/`.
`validate_release.py` re-checks the assembled set and writes `VALIDATION_REPORT.md`.

## Conventions

The analytical conventions are defined once, in
[ANALYSIS_DECISIONS.md](ANALYSIS_DECISIONS.md): Likert 1-5 coding with the administered
anchors (Disagree / Somewhat disagree / Neutral / Somewhat agree / Agree); NVT/DK handling
and the not-applicable share (`nvt_pct`); directional Top-2 (reverse-scored items relabelled to the positive direction and
marked `(R)`); count-weighted pooling; family-only Control and Effort; and no small-cell
suppression. Professional time-estimate items use organisation-specific scales and are out of
the publication scope (kept private only). N=You and Levvel used slightly different
questionnaires; the `orgs_included` column in Additional file 3 marks the few items only one organisation
asked (see ANALYSIS_DECISIONS.md).

## Testing

```bash
pip install -r requirements-dev.txt
pytest
```

`tests/` runs on fully synthetic fixtures (no real respondent rows or open text), plus
validation of the public mapping workbooks and consistency checks on the assembled Additional files 1-3
(stable item IDs, family-only themes). CI (`.github/workflows/ci.yml`, Python 3.9 and 3.11)
runs the same suite and never touches `data/raw/` or the private qualitative workbook.

## Reproducibility scope

- Computational reproduction (exact numbers and figures): possible for an authorised user
  who has the private `data/raw/`.
- Inspectability: the full analysis code and mapping are public.
- Verification without raw data: aggregate results, figures, and metadata are public.
- Testability: synthetic-fixture unit and integration tests run in CI without private data.

## Known issues / pending decisions

Nothing blocking. `CITATION.cff` and `LICENSE` are complete; the only open addition
is the `preferred-citation` block once the article is accepted.

Resolved (see `ANALYSIS_DECISIONS.md`): the Effort family items FAM-INSP-a/b/c (the Levvel-child
Forms display fault was corrected per the Forms design, so "Beet je mee oneens" reads as position
2, "1 tot 3 maanden" as position 4, and "Meer dan 3 maanden" as position 5, leaving all responses
valid Likert on a unified denominator); the response-scale anchor labels (Disagree / Somewhat
disagree / Neutral / Somewhat agree / Agree, not "Completely ..."); and the redaction
sign-off for the qualitative quotes.

Resolved 2026-07-28: the four items whose administered wording had been truncated in the
Microsoft Forms export (FAM-UITW-b, FAM-INSP-b, and the shared professional Overview open
prompt) were completed from the original Forms design and retranslated; the questionnaires
have no remaining truncations.
